01 · As três camadas

Arquitetura em camadas (Bronze, Prata, Ouro)

Cada camada tem uma responsabilidade clara e pode ser recriada do zero (idempotente). A fronteira entre "o dado que chegou" e "o dado que eu decidi" fica na passagem da Bronze para a Prata.

02 · Aula 1

Ingestão · do arquivo para a tabela
bronze · pipeline/ingestao.py

Ler os .dbc do SIH sem mudar nada

Baixo os arquivos do DATASUS (27 UFs), converto de .dbc para um parquet único e gravo no schema bronze com todas as colunas como texto. Regra da camada: nenhuma conversão, nenhuma linha descartada.

Conferência: a ingestão termina em 1.256.785 registros nas três tabelas (1.238.763 internações + 12.451 CID-10 + 5.571 municípios).

03 · Aula 2

Transformação · ler o dado ≠ confiar no dado
prata · pipeline/transformacao.py

Tipar e decodificar os códigos do SIH

Aqui mora o julgamento. O SIH guarda tudo em código: converto VAL_TOT para DECIMAL (dinheiro), DT_INTER (AAAAMMDD) para data, decodifico SEXO (1→Masculino, 3→Feminino), MORTE para booleano, e derivo a UF e a região a partir do código IBGE do município. Uma linha = uma internação (AIH).

Conferência: 1.238.234 linhas na prata (529 sem valor, removidas de propósito). A idade usa COD_IDADE (a unidade do SIH): bebês medidos em dias/meses agora caem em "< 1 ano", que subiu de 1,4% para 4,9% da base. No mart por estado, SP lidera com 249.866, seguido de MG (135.542) e RJ (78.503).

04 · Aula 3

SQL · o grão antes do SELECT
ouro · sql/marts/*.sql

Dez marts escritos em SQL, cada um respondendo uma pergunta

A camada ouro é SQL puro: cada arquivo .sql declara o grão na primeira linha e vira uma tabela. Uso GROUP BY, agregações (COUNT, SUM, AVG, MEDIAN), JOIN com os dicionários, CASE WHEN para as faixas etárias, FILTER para a mortalidade e window functions (ROW_NUMBER, RANK, SUM() OVER) com CTE e HAVING nos marts de ranking. O Python (marts.py) só executa os arquivos; a regra de negócio mora inteira no SQL.

Exemplo real: o mart que compara os estados (o coração do painel).

-- Grão do resultado: uma UF.
SELECT
    uf,
    regiao,
    COUNT(*)                                                   AS internacoes,
    ROUND(SUM(valor_total), 2)                                 AS valor_total,
    ROUND(AVG(valor_total), 2)                                 AS custo_medio,
    ROUND(AVG(dias_permanencia), 1)                            AS dias_medio,
    ROUND(100.0 * COUNT(*) FILTER (WHERE morte) / COUNT(*), 2) AS taxa_mortalidade_pct
FROM prata.internacoes
WHERE uf IS NOT NULL
GROUP BY uf, regiao
ORDER BY internacoes DESC;

Insight real: o diagnóstico que mais interna no Brasil é o parto único espontâneo (CID O800, 49.288 internações), seguido de pneumonia e infecções, exatamente o perfil do SUS.

05 · Aula 4

Dashboard e testes
dashboard · app.py + painel.py

Painel interativo por estado (Streamlit)

Abre na visão Brasil e tem um seletor de estado que recorta tudo. Tem mapa coroplético, ranking de UFs, gráfico de rosca por região, custo médio por estado, top diagnósticos, série diária e perfil por idade e sexo. A tela nunca calcula: todo número sai pronto de um mart.

testes · test/

Testes com pytest, cobertura acima de 90%

Testes unitários com dado inventado (nunca o banco real), cobrindo a ingestão, a transformação, os marts, o painel e as regras de qualidade. Meta do desafio: 70%. Resultado: acima de 90%.

qualidade · pipeline/qualidade.py

Checagens que travam o build

A conferência que a gente faria na mão virou código: regras SQL que falham o pipeline se um número não fechar. "As partes somam o todo" (o perfil e o por_estado somam o total dos KPIs), "o grão é real" (count = count distinct aih), "dentro do domínio" (idade ≥ 0, mortalidade entre 0 e 100, UF entre as 27 válidas). Roda no CI a cada push.

06 · Como rodar

Do zero ao dashboard
git clone https://github.com/Nayanearaujo/pipeline-saude-sus.git
cd pipeline-saude-sus
uv sync

uv run python baixar_dados.py            # baixa o SIH-RD de abril/2026
uv run python gerar_dicionarios.py       # nomes de CID-10 e municípios

uv run python executar.py                # bronze -> prata -> ouro -> qualidade

uv run streamlit run app.py              # o dashboard
uv run pytest --cov                       # os testes (cobertura > 90%)
uv run ruff check .                       # estilo e imports
Os dados brutos não ficam no repositório (boas práticas: são grandes e reproduzíveis). O script baixar_dados.py os regenera na máquina.

07 · Sobre a IA

O que a IA errou, e como percebi

A IA escreveu o encanamento a partir de specs; o trabalho foi conferir. Três erros que não estouravam, só apareciam como número errado:

  • A série diária não somava o total. O arquivo RD é por competência (mês de pagamento), não por data de entrada: metade das AIH de abril entrou em meses anteriores. O gráfico passou a dizer que o eixo é data de entrada e que, por isso, não soma o KPI.
  • A idade ignorava a unidade. O SIH traz COD_IDADE (dias, meses, anos); sem ele, 60.840 bebês medidos em dias/meses caíam em faixas de adulto. Corrigido, "< 1 ano" foi de 1,4% para 4,9%.
  • Os nomes de doença sumiam. Sem internet, o dicionário caía em modo neutro ("CID O800"); o JOIN funcionava mas juntava com rótulo vazio. Com a fonte oficial, 12.451 nomes reais entram.

A lição do curso, na prática: erro em código de dados não lança exceção, aparece como número errado, e só a conferência pega. Por isso a conferência virou código em pipeline/qualidade.py.
